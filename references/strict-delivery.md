# 光学宏严格交付规范

## 目标

本规范适用于 CODE V Macro-PLUS、Zemax ZPL 和 ZOS-API。目标是阻止未经证明的语法组合进入交付，并明确静态审查、软件编译和实际运行之间的差别。

## 证据与语法冻结

每个高风险语句在编写时按以下顺序取证：

1. **A 目标版本实机证据**：相同结构已在用户目标版本成功执行。
2. **B 官方同形示例**：官方宏中命令、限定符顺序、命令模式和前后状态一致。
3. **C 官方完整语法**：官方手册给出该完整形式。
4. **D 推断组合**：只知道各片段分别合法，组合形式没有证据。

交付宏只允许 A/B/C。发现 D 时：

- 改写成更简单的 A/B/C 形式；
- 或先生成最小烟雾测试，在目标软件中验证；
- 无法验证则标注为未完成，不能藏在完整宏里。

B/C 级证据必须能追溯到包内相对文件、行号或 PDF 页码；A 级证据必须记录目标软件版本、实际调用和原始输出。仅写“见官方手册”或“官方宏有类似写法”不算完成取证。

“官方手册包含这些关键字”不等于“任意组合均合法”。特别禁止自行组合：

- CODE V 命令限定符、表面/公差范围、标签、变焦限定符和动态变量。
- ZPL 关键字参数、分析向量布局、操作数参数和 Macro Solve/ZPLM 返回形式。
- ZOS-API 枚举、分析设置接口、结果类型、工具生命周期和编辑器列。

## 任务分解

先把宏拆成独立证据块：

1. 输入与单位。
2. 系统类型和配置检查。
3. 数据读取或对象识别。
4. 临时副本和状态保存。
5. 修改命令。
6. 分析命令及其命令模式。
7. 结果提取与布局校验。
8. 用户结论输出。
9. 统一清理和失败恢复。

每块只采用一种已证明模式。不要在一个长序列里同时试验多个新语法。

## CODE V 门槛

- 所有 `NUM/STR/LCL/GBL/SHR` 定义位于第一条可执行语句之前。
- `RFD` 写在第一条可执行语句之前，给允许省略的参数定义默认值。必填 `#n` 可以没有对应的 `RFD`，调用说明须明确其位置和含义。Macro Manager 的 `ARGn DEFAULT` 与命令行默认值分别核对。
- 区分立即命令和需要 `GO` 的命令模式；TOR、MTF、LIB、优化和绘图块必须有明确边界。
- 只在数据库项支持的上下文使用 `IC/JC`、`S/F/W/Z/T` 限定符。
- 不把动态变量紧贴到未经官方示例证明的限定符中。
- `STR_TO_NUM` 前验证完整输入 token；跨版本解析默认使用 `LENSTR/LOCSTR/SUBSTR`，未经证据不依赖 `SPLIT`。
- 单配置不查询只对真正多重结构安全的数据库项，例如先分支 `(NUM Z)` 再使用 `(POS Z...)`。
- 多重结构的半径、厚度、材料和状态读取明确 `Z`；镜片号、材料区域号和表面号先映射再生成范围。
- 捕获前检查 `(BUF.ON)` 和 `(BUF.EMP B0)`，只清理本宏接管的内容。`BUF FND` 后先确认成功，随后按有效行列、单元格类型和结果块数量验证读取。复制 B0 时先将当前目标移到自有的 B1 或更高编号。
- 公差类型、对象范围和单位逐项核对；角度由度转换为弧度，偏心按 `(DIM)` 转换；建立偏心/倾斜公差前检查已有 `(TYP DEC)`。
- 分析频率、方位、视场、波长、配置、采样和单位写入结果头，并验证输入范围和分析截止条件。
- `OUT/VER` 关闭后不能依据最后可见回显定位错误；诊断版使用 `WRI "STEP ..."`。
- 修改镜头前创建唯一临时副本，所有正常失败路径进入一个清理出口。
- 认识到 CODE V 运行时错误可能直接中止序列并跳过清理；调试版不得默认覆盖原文件。
- TOR/MTF 等原始表不是交付结果，先输出最坏对象、条件和结论，再输出明细。
- 结果排名使用首值标志或合法范围外哨兵初始化；全零、并列和空数据必须产生明确状态，不能输出默认 G0。
- 图形同时配套数值表；离散工程数据默认 `LIN PNT`，`SPL PNT` 仅用于确实连续且允许插值的量，`DPO` 标签不超过 24 字符。

## ZPL 门槛

- 每条命令独占一行；赋值 `=` 与比较 `==` 不混用。
- `FOR variable, start, stop, increment` 与 `NEXT` 成对；浮点循环优先改为整数索引。
- 每个 `IF` 有 `ENDIF`；每个 `GOSUB` 有对应 `SUB`；每个子程序至少有 `RETURN`；主程序在首个 `SUB` 前有 `END`。
- `OPEV` 固定七个参数；操作数代码、参数意义和单位来自当前官方帮助。
- `RAYTRACE/RAYTRACEX` 后检查错误与渐晕状态，不只读取坐标。
- 文件输出最终恢复 `OUTPUT SCREEN`；文件、数组、窗口、锁和更新暂停均成对释放。
- Macro Solve 必须短小、只读并含有效路径上的 `SOLVERETURN`；禁止 `UPDATE`、`INPUT`、编辑器修改和递归触发。
- ZPLM 使用 `OPTRETURN datafield, result`，datafield 为 0..50；宏编号、文件名和 Data 0 执行规则按当前帮助核对。
- `Check Obsolete Syntax` 用于发现过时语法。L2 保存目标 OpticStudio 实际执行并到达预期检查点的证据。

## ZOS-API 门槛

- 连接代码由目标版本 Application Builder 生成，不手写旧 DLL 路径和旧枚举整数。
- 明确 Standalone、Interactive Extension、User Analysis、User Operand 或 User Extension。
- 验证许可证、连接、`PrimarySystem` 和顺序/非顺序模式。
- 修改原系统前另存副本；默认不覆盖用户镜头。
- 分析对象执行后读取实际结果集合、维度、轴和单位，并关闭分析对象。
- 同一时间只打开一个 Tool；Batch Ray Trace、优化、公差和导出工具必须在 `finally` 中关闭。
- Standalone 可关闭其创建的应用；Interactive Extension 不关闭用户应用。
- 捕获具体异常并清理资源；禁止空的 `except: pass`。
- Python 语法检查只能证明 Python 可解析，不能证明当前 ZOS-API 对象、枚举或许可证可用。

## 交付分级

交付时列出：

```text
验证等级：L1 静态审查
已验证：结构、变量、已知危险模式、官方同形证据
未验证：目标 CODE V/OpticStudio 编译与运行
```

按 `SKILL.md` 定义记录 L2-L4。对分析、转换或批处理宏，用 [实机与数值验收](runtime-verification.md) 记录数值基准、误差和状态复查。一个用例的结论只覆盖记录中的版本、系统和参数。

## 禁止表述

未达到对应等级时禁止：

- “保证没有语法错误”
- “完整无误地运行”
- “静态检查证明可运行”
- “兼容所有版本”

改为准确说明证据、目标版本和剩余验证。
